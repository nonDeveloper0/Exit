# 조장 권한 분리 — 기획 (보류, 나중에 결정)

> ⚠️ 이 문서는 **기획안**입니다. 아직 구현하지 않았습니다. 방향 확정 후 착수합니다.

## 목표

한 조에서 **조장 기기만** 능동 기능(증거 수집 / 최종 투표 / 심문권 사용)을 쓰고,
**나머지 조원 기기는 증거함을 뷰어처럼 열람만** 하도록 역할을 분리한다.

- 지금은 역할 구분이 없어, 같은 조 번호로 입장한 모든 기기가 동일한 전체 권한을 가진다.
- 특히 **투표가 조원 수만큼 중복 제출**될 수 있는 문제를 막는 것이 핵심 동기.

## 권한 표 (목표)

| 기능 | 조장 | 조원(뷰어) |
|------|------|-----------|
| 증거함 열람 (`/evidence`) | ✅ | ✅ |
| 용의자 파일 / 수사 현황 열람 | ✅ | ✅ |
| QR 스캔 증거 수집 | ✅ | ❌ (버튼 숨김/비활성) |
| 최종 투표 제출 | ✅ | ❌ |
| 심문권 사용 처리 | ✅ | ❌ |

## 조장 지정 방식 (관리자)

- `/admin`에 **조별 조장 이름 입력** 섹션 추가.
- 저장 위치 후보: `game_state`에 `leaders JSONB`(예: `{ "1": "홍길동", "2": "김철수" }`) — DB 스키마 최소 변경. 관리자 저장 → Realtime 전파.

## 조장 여부 판정 (기기 관점)

랜딩에서 각 기기가 입력한 이름(`exit2026_team.leaderName`)과 관리자가 등록한 그 조의 조장 이름을 비교.

- **일치 → 조장(전체 권한)**, 불일치 → 조원(뷰어).
- Realtime으로 `leaders` 변경 시 즉시 권한 재판정.

### 판정 방식의 리스크 / 미결정 사항

1. **이름 매칭의 취약성** — 동명이인, 오타, 공백/대소문자 차이로 오판정 가능.
   - 대안 A: 이름 대신 **조장 전용 코드/PIN**을 관리자에서 발급 → 조장 기기만 입력.
   - 대안 B: 이름 정규화(trim + 공백 제거) 후 비교 (간단하지만 완벽하지 않음).
2. **조장 기기 분실/교체** — 관리자에서 조장 이름(또는 코드) 재지정으로 이관 가능해야 함.
3. **조장 복수 허용?** — 조당 1명 고정 vs 2명까지 허용할지.
4. **입장 순서 문제** — 관리자가 조장을 지정하기 전에 이미 입장한 기기들의 권한 처리(기본 뷰어? 기본 전체?).
5. **UX** — 조원 기기에서 수집/투표/심문 버튼을 "숨김"으로 할지 "비활성 + 안내문(조장만 가능)"으로 할지.

## 구현 시 영향 파일 (예상)

## 미결정 → 확정 필요

- 조장 판정: **이름 매칭 vs 코드/PIN** (권장: 코드/PIN — 오판정 없음)
- 조원 능동 버튼: **숨김 vs 비활성+안내**
- 조장 복수 허용 여부
- 지정 전 입장 기기의 기본 권한
