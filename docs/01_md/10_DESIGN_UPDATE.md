# DESIGN UPDATE — 방향 확정 (오프라인 헌팅 중심)

> 이 문서는 기존 QR 열람 중심 설계에서 **오프라인 단서 헌팅 + 웹 보조** 방향으로
> 전환한 확정 사항을 담는다. 아직 코드로 구현되지 않은 **기획 기준 문서**다.
> 구현 상태는 `progress.md`를 본다.

## 핵심 전환

단서 대부분이 **물리 오브젝트**(금고·USB·파쇄지·자물쇠 등)로 바뀌었다.
따라서 "웹이 단서를 보여준다"는 전제를 버리고, 웹은 오프라인 헌팅을 **보조**한다.

- **추리는 100% 참여자 몫.** 웹은 방향을 짚어주거나 판정하지 않는다.
- 오프라인에서 직접 찾는 재미를 유지하되, 찾은 단서를 **모으고 되짚는** 용도로 웹을 쓴다.

## 웹의 역할 (확정)

| 역할 | 내용 |
|------|------|
| ① 단서 수집(공유 보관함) | 조가 찾은 단서를 실시간 공유. 요약 + 이미지 보관 |
| ② 보조 설명 | 각 단서에 맥락 한 줄 정도. **판정·소거 표현 없음** |
| ③ 방송 / 진행 제어 | 디지털 단서(녹음·CCTV·협박메시지) 전체 공개, 투표, 엔딩 (admin) |

> ❌ 하지 않는 것: "혐의 없음" 같은 소거·판정, 추리 방향 유도, 정답 힌트.

## 단서 등록 방식 — QR + 코드 병행

QR을 걷어내지 않는다. 두 경로 모두 **같은 수집 액션**으로 연결된다.

- **QR 스캔**: 현장에 붙는 위치성 단서 (기존 `/qr/[slug]` 유지)
- **코드 입력**: 퍼즐을 풀어야 나오는 단서 (원소기호·파쇄지 조합·자물쇠 결과 등)
- 단서마다 운영자가 "QR / 코드" 중 등록 경로를 고른다.
- 둘 다 같은 보관함·용의자 화면으로 들어간다.

## 용의자 화면 — 중립 라벨

- 용의자별 관련 단서를 **중립 라벨(관련 단서 ①②③)** 로 평평하게 나열한다.
- 카테고리(동기/스토리라인/알리바이) 라벨은 **UI에 노출하지 않는다** — 라벨 자체가 추리 힌트가 되기 때문.

## 단서 기획 내부 뼈대 (UI 비노출)

각 용의자 단서는 아래 3단계로 **기획**한다. UI에는 드러내지 않는다.

| 단계 | 역할 |
|------|------|
| 동기 | 살인 동기 |
| 스토리라인 | 사건 당일 정황 |
| 알리바이 | 용의자를 **제외**하는 요소 — 찾기 어렵게 배치 |

- 알리바이는 소거의 근거지만, 웹이 "제외됨"을 표시하지 않는다. 참여자가 스스로 판단.

## 기존 코드 재활용

| 기존 기능 | 새 기획에서의 쓰임 |
|-----------|------------------|
| `pairings` (짝 조 증거 공유) | **독극물 레시피 맵핑** — admin이 매칭한 2개 조끼리만 공유 |
| `COMMON_EVIDENCE` (전체 공개+공지) | 폭행 녹음·협박메시지·CCTV 전체 방송 |
| 심문권 (`interrogationTriggerId`) | 특정 단서/코드 획득 시 심문권 지급 (예: 채소장 원소기호 단어) |
| `LOCKED_EVIDENCE` + `EVIDENCE_QUIZ` | 코드 입력 게이트의 기반 (일반화 예정) |
| 랭킹 / 투표 / 엔딩 / admin | 그대로 유지 |

## 조 구도

**혼합** — 기본은 조별 진행, 일부 단서는 범위를 달리한다.

- 조별: 대부분의 단서
- 짝 조 공유: 독극물 레시피 맵핑 (`pairings`)
- 전체 공개: 방송 단서 (`COMMON_EVIDENCE`)
