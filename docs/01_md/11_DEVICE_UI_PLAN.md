## 이 세션에서 확정된 것

### 1. "전 기기 동시재생" 폐기
80명 폰에서 동시에 소리를 내는 연출은 기술적으로 불가에 가까워 폐기.

- iOS Safari·Android Chrome 모두 사용자 제스처 없는 `audio.play()` 차단 → Realtime 신호를 받아도 소리 못 냄
- 폰 잠금·백그라운드 시 브라우저가 탭 정지 → Realtime 신호 자체를 못 받음 (수사 중 대부분 이 상태)
- iOS는 웹 진동 API 없음, 웹 푸시는 PWA 설치 온보딩 필요 → 120분 이벤트에 무리
- **결론**: 물리 스피커(11층)가 주 채널, 웹은 보조

### 2. 속보(브리핑) 시스템 — "동시 도달" 대신 "놓치지 않음" 보장
- admin이 속보 발행 → DB 저장 + Realtime 전파
- 앱 열린 기기: 즉시 전체화면 배너
- 잠겨 있던 기기: **다시 앱 열 때 안 본 속보 자동 표시** (DB에 있으니까)
- 홈에 **속보 아카이브** → 늦게 합류/놓친 사람 따라잡기
- 스피커로 "지금 폰 확인하세요" 한마디 → 사실상 전원 도달

### 3. 폭행 녹음 등 오디오 → "재생 버튼 테이크오버"로 격하
- 스피커로 트는 게 메인, 웹은 직후 속보 "녹음 파일 입수" + 증거함에서 **다시 듣기**(탭 재생이라 자동재생 문제 없음)

### 4. 수신전화 연출 (확정 — 꼭 넣기)
- admin 활성화 → 그 시점 이후 앱 여는 기기마다 **수신 전화 UI** 표시
- "받기" 탭 = 사용자 제스처 = 오디오 재생 합법
- 전원 동시는 아니지만 "내 폰에 사건 속 전화가 왔다" 체험 유지. 각자 받는 타이밍이 달라 웅성거림이 퍼지는 것도 연출

#### 구현 상태 (2026-07-11)
- `/admin` 게임 진행 제어에 **수신전화 연출** 카드 추가: `전화 걸기` / `전화 종료`
- 활성 상태 저장: `team_evidence_items`에 `pair_id='__global'`, `evidence_id='_incoming_call'`, `type='incoming_call'`
- 전역 오버레이: `IncomingCallOverlay`가 Realtime + 초기 조회로 활성 상태를 감지
- 참가자가 `받기`를 누르면 `public/audio/incoming-call.mp3` 재생
- 한 번 처리한 전화는 기기별 localStorage(`exit2026_incoming_call_handled`)에 기록. 관리자가 다시 `전화 걸기`를 누르면 `created_at`이 갱신되어 새 전화로 다시 표시됨
- 랜딩(`/`), 관리자(`/admin`), 엔딩(`/ending`)에서는 전화 오버레이를 띄우지 않음

#### 추가 확정 (2026-07-11) — 밀어서 받기 + 음성 메시지 수집

**A. 받기 UX = 밀어서 받기 (구현 완료)**
- 첫 화면 `받기` 버튼(탭) → **밀어서 받기 슬라이더**로 교체. 노브를 트랙 폭 85% 이상 끌어야 연결(탭만으론 안 받아짐), 미만이면 원위치.
- pointer 이벤트로 터치/마우스 공용. `거절`은 하단 텍스트 버튼으로 유지.
- 파일: `src/components/IncomingCallOverlay.tsx`, `src/app/globals.css`(`slide-hint` 애니메이션).

**B. 전화 = "음성 메시지" 증거를 남긴다 (기획 확정, 미구현)**
문제: 지금 전화는 연출로만 소비돼 사라짐 → 중간에 끊으면 단서 유실. §2·§3 원칙("놓치지 않음" + "증거함 다시 듣기")에 맞춰 전화 오디오를 **증거함에 저장되는 재생 가능한 단서**로 격상.

- **수집 시점**: **받았을 때만** — `밀어서 받기`로 연결 성립 시 그 조 보관함에 즉시 등록. 청취 완료 불필요, 중간 종료해도 남음.
  - ⚠️ **스코프**: 거절·미응답 조는 **미수집**(운영자 결정). "안 받아도 수집"은 의도적으로 제외.
  - insert 트리거는 `accept()` **진입 즉시** 권장 — 자동재생이 차단(`audioError`)돼도 "받기"는 눌렀으니 수집돼야 함.
- **랭킹 집계**: **제외**.
- **재생**: 증거함 '다시 듣기'는 `audioUrl` 있으면 이미 동작 → 추가 작업 없음.

**구현 스펙 (핸드오프)**
1. `data.ts`: 음성 메시지 증거 1종 추가 — 예 `{ id: "CALL01", title: "음성 메시지", description: "…", audioUrl: INCOMING_CALL_AUDIO_URL }`.
2. `IncomingCallOverlay.tsx`: `useTeamEvidence().collect`를 받아, `accept()` 진입 시 `collect("CALL01")` 호출(이미 수집돼 있으면 collect가 무시함).
   - `collect`는 `type:"collected"`로 insert하므로 증거함에 그대로 노출됨.
3. **랭킹 제외**: `useAllTeamsProgress`의 count 집계와 `total`(=`EVIDENCE.length`)에서 `CALL01`을 빼는 예외 처리 1줄. (별도 `type` 분리 대신, 증거함 노출을 살리기 위해 `type:"collected"` 유지 + 랭킹에서만 제외하는 방식 권장.)
4. reset은 조 `team_evidence_items` 전체 삭제라 자동 정리됨 — 추가 작업 없음.

## 디제틱 기기 UI — 핵심 개념

**참여자 폰(또는 실물 노트북)에서 열리는 웹페이지가 "기기 화면인 척" 연기.**
지금 QR 찍으면 증거 카드가 뜨는 것과 **구조는 동일**, 페이지 생김새만 노트북/아이패드처럼 꾸민다.

- 진입: 현장 소품(노트북 사진 인쇄물·고장 노트북·카드 등)에 QR 스티커 → 스캔 → `/device/[id]`
- 기존 `/qr/[slug]` 인프라 재활용 — slug가 증거 대신 **기기**를 가리키게 확장
- 잠금화면 상태로 먼저 보이고, 오프라인에서 찾은 비번을 넣어야 열림 → 헌팅 동기 유지
- **해제 = 수집으로 통일**: 조가 열면 콘텐츠가 조 보관함에 수집됨. 조원이 나중에 QR 찍으면 이미 수집돼 있어 잠금 해제 상태로 보임 → 별도 unlock 동기화 테이블 불필요

## 나사장 노트북 — 실물 노트북 + 2단 잠금 (확정)

폰 가짜 노트북 데모를 만들어 본 뒤 **실물 노트북** 방향으로 결정.
운영팀 노트북 1대에 목업 HTML을 **전체화면(키오스크)** 으로 띄우고 6조가 돌려 씀.

핵심: 노트북 = **Exit 웹사이트의 또 다른 클라이언트**. 조별 비번이 "몇 조인지" 신분증 역할을 해, 노트북에서 수집한 걸 그 조 Supabase 보관함에 바로 기록.

### 2단 잠금 구조
```
① 잠금화면 = 조별 비번 (신분 식별 + 진입)
   → Exit 모바일 웹에서 문제를 풀면 조마다 다른 노트북 비번 발급
   → 그 값을 나사장 노트북에 입력  (앱이 발급하므로 위조 불가 + 자동 신분 인식)
② 바탕화면 → 비밀장부.xlsx 클릭 → 엑셀 자체 비번(공통, 감사패에서 획득 예: 1980)
   → 정답 입력 시 열람 + 그 조 수집함에 자동 전송
```
- **협박메시지 → 오프라인 단서로 이동** (노트북에서 제거)
- 두 비번이 서로 다른 오프라인/앱 단서에서 나와, 한 노트북에 두 갈래 헌팅이 모임

### 세션 위생 (공용 1대라서)
- 잠금화면 = 기본 상태
- 해제 시 바탕화면 상단 **"● N조 세션"** 배지 → 내 조로 등록 중임을 확인
- **닫기(잠금) 버튼** or **90초 무입력 자동 재잠금** → 다음 조가 남의 세션에 안 얹히게

## 출입관리 아이패드 — 조 구분 문제

사원번호는 **공통**이라 신분증이 못 됨(노트북과 달리 "비번=조 식별"이 안 통함). 신분을 따로 받아야 함.

| 방식 | 방법 | 비고 |
|---|---|---|
| **A. 방문 조 체크인 (채택)** | 사원번호 앞에 "방문 조 번호" 입력 단계 | 출입관리 기기라 "방문 조 확인"이 연출상 자연스러움(체크인 키오스크). 자가신고 위조는 협동·감독 상황이라 리스크 낮음, 세션 배지로 실수 즉시 표면화 |
| B. 앱이 조별 코드 발급 | 노트북처럼 앱 코드 입력 | 위조 불가하나 "사원번호=공통" 컨셉 사라짐 |
| C. 사원번호 + 조번호 | `2201-3` | 노트북과 같은 패턴이나 순수 공통 아님 |

→ **A안 채택.** 아이패드 목업(`device-ipad-demo.html`)은 A로 작성됨.
