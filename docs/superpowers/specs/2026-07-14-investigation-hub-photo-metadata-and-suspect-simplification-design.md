# 수사본부·사진 메타데이터·용의자 화면 개편 설계

## 목표

수사 방법과 전체 조 사진 현황을 수사본부에 통합하고, 문서 판독에 적합한 고화질 사진과 인물·장소 메타데이터를 제공한다. 용의자 화면은 머그샷, 심문권, 수사 노트만 남긴다.

## 수사본부 통합

하단 네비게이션의 `현황` 탭과 `/ranking` 경로를 제거한다. `/home`의 기존 `수사 방법` 바로 아래에 `전체 수사 현황`을 배치하고, 기존 랭킹의 실시간 조별 사진 장수, 짝 조 그룹화, 내 조 강조, 순위 색상, 실시간 상태를 그대로 옮긴다. `useAllTeamsProgress`는 유지하되 소비처를 `/home`으로 바꾼다.

## 사진 품질과 메타데이터

새 업로드는 긴 변 2048px, JPEG 품질 0.90으로 압축한다. 이는 기존 1080px·0.72보다 문서 텍스트 판독성을 높이며 원본 그대로 업로드하지 않아 전송량도 제한한다. 기존 사진 파일은 재처리하지 않는다.

사진 등록 시 기존 `증거 설명`(DB 호환 컬럼 `caption`, 20자 제한), 관련 인물, 관련 장소를 입력한다. 장소 선택값은 `미지정`, `자재 물류창고(사건현장)`, `나사장 사무실`, `나팀장 사무실`, `채소장 연구실`이다. 관련 인물만 증거함에서 필터링하며 장소는 폴라로이드와 확대 화면에 표시만 한다.

`photo_evidence`에 nullable `location_tag`와 영구 `evidence_number`를 추가한다. `evidence_number`는 DB가 자동 부여하는 단조 증가 번호이며 폴라로이드 좌상단의 `#번호`로 표시한다. 기존 행에는 번호를 한 번 부여하고 장소는 null로 둔다. 번호는 보드 정렬·필터·새 업로드에 영향을 받지 않는다.

## 증거함 편집과 레이아웃

증거함은 `전체`, 각 관련 인물, `미지정` 필터만 제공한다. 사진 확대 화면에서 관련 인물과 장소를 수정할 수 있으며, 업데이트는 `photo_evidence` 메타데이터만 변경한다. 기존 UPDATE Realtime 구독으로 같은 조와 짝 조 구성원에게 즉시 반영된다.

등록 시트는 하단 내비게이션과 겹치지 않도록 내비게이션 높이 이상의 하단 안전 여백을 두고, 좁은 화면에서는 시트 내용이 세로 스크롤된다. 모든 UI 표기는 `캡션` 대신 `증거 설명`을 사용한다. 폴라로이드 하단 설명은 손글씨 계열 시스템 폰트 스택을 사용하고, 인물·장소 칩을 함께 표시한다.

## 용의자 파일 단순화

용의자 카드의 머그샷과 이름은 유지한다. 펼친 내용에서는 동기, 설명, 관련 사진, 관련 사진 라이트박스, 사용하지 않는 관련 단서 블록을 제거하고 심문권과 수사 노트만 남긴다.

모든 A~E 용의자에 심문권 영역을 표시한다. `INTERROGATION_QUIZZES`에 연결된 용의자는 기존 획득·사용 흐름을 적용한다. 아직 QR 퀴즈가 없는 용의자는 `QR 문제 연결 대기 중` 잠금 상태로 표시한다. 추후 퀴즈 매핑을 데이터에 추가하면 화면 구조 변경 없이 즉시 기존 획득 흐름을 사용한다.

## 데이터베이스 마이그레이션

Supabase에서 다음 마이그레이션을 실행한다.

1. `location_tag text null`을 추가한다.
2. `evidence_number bigint`와 전용 sequence를 추가하고, 기존 사진에는 `created_at`, `id` 순으로 번호를 부여한다.
3. `evidence_number`의 기본값을 sequence의 `nextval`로 지정하고 `NOT NULL`, `UNIQUE` 제약을 적용한다.

애플리케이션은 새 컬럼을 조회·삽입·UPDATE에 반영한다. 마이그레이션 전에는 새 필드를 전제로 화면을 배포하지 않는다.

## 오류 처리와 검증

- 사진 메타데이터 저장 중에는 저장·취소를 비활성화하고 실패 시 시트를 유지한 채 재시도 문구를 표시한다.
- 필터 판정은 순수 함수 테스트로 검증한다.
- 고화질 압축, 수사본부 랭킹, 등록 시트 안전 여백, 인물·장소 표시와 수정, QR 미연결 심문권을 브라우저에서 점검한다.
- `npm test`, `npm run lint`, `npm run build`를 실행한다. 기존 린트 경고는 신규 오류로 취급하지 않는다.
