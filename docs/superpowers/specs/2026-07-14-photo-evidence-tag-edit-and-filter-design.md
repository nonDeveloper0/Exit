# 사진 증거 태그 편집 및 용의자 필터 설계

## 목표

참가자가 증거함에 저장한 사진의 관련 인물 태그를 저장 후에도 같은 조 및 짝 조 구성원과 함께 수정하고, 용의자별로 사진을 빠르게 필터링한다.

## 범위

- `/evidence` 라이트박스에 `관련 인물 수정` 진입점을 추가한다.
- 수정 시 기존 태그를 선택값으로 한 드롭다운과 저장/취소 동작을 제공한다.
- 태그는 `photo_evidence.suspect_tag`만 갱신한다. 이미지와 캡션은 변경하지 않는다.
- 상단에 `전체`, 각 `PHOTO_TAGS` 인물, `미지정` 필터를 추가한다.
- 필터는 현재 기기에만 유지하는 화면 상태이며 URL이나 DB에 저장하지 않는다.

## 데이터와 실시간 동기화

`usePhotoEvidence`에 `updatePhotoTag(photoId, suspectTag)`를 추가한다. 이 함수는 `photo_evidence` 행의 `suspect_tag`를 `null` 또는 선택한 태그 값으로 업데이트한다. 기존 UPDATE Realtime 구독이 갱신된 행을 모든 같은 조·짝 조 기기에 반영한다. 별도 테이블, Storage 파일 처리, 마이그레이션은 필요 없다.

## 화면 동작

사진 카드를 누르면 기존 라이트박스가 열린다. 라이트박스에서 `관련 인물 수정`을 누르면 편집 시트가 열리고, 현재 태그가 선택된 드롭다운에서 인물 또는 `미지정`을 선택할 수 있다. 저장 성공 시 시트를 닫고 라이트박스의 태그 표시와 보드가 실시간으로 갱신된다. 실패 시 시트를 유지하고 오류 문구를 표시한다.

증거함 보드 위에는 가로 스크롤 가능한 필터 칩을 둔다. `전체`가 기본값이며 선택한 태그와 일치하는 사진만 보인다. `미지정`은 `suspect_tag`가 null인 사진만 표시한다. 해당 조건의 사진이 없으면 빈 결과 안내를 표시한다. 제외된 사진도 기존과 같이 표시·필터링한다.

## 오류 처리와 검증

- 수정 저장 중에는 저장·취소를 비활성화해 중복 요청을 막는다.
- Supabase 업데이트 실패 시 사용자가 다시 시도할 수 있는 오류 문구를 표시한다.
- 단위 테스트가 없는 저장소이므로 lint와 production build를 실행하고, 코드 수준에서 훅의 갱신 요청과 화면의 필터/편집 상태를 확인한다.

## 변경 파일

- `src/lib/usePhotoEvidence.ts`: 태그 갱신 API와 저장 상태를 제공한다.
- `src/app/evidence/page.tsx`: 용의자 필터와 라이트박스의 태그 편집 시트를 제공한다.
- `progress.md`: 작업 시작 및 완료 내역을 기록한다.
